# 카드 1: 공개 영역과 비공개 영역의 분리 및 경계 구축 보고서

## 1. 개요 및 목적
1번 과제에서 구축한 신재원의 공개 소개 페이지(`index.html`)는 누구나 접근할 수 있도록 100% 온전히 유지하면서, 나만의 비공개 자료를 안전하게 보관할 수 있는 **[🔐 나만의 시크릿 볼트 (Private Vault)]** 자리를 새로 구축했습니다.  
공개 영역과 비공개 영역의 경계를 시각적·물리적·네트워크 계층에서 명확히 분리하여, 패스키 인증 없이는 비공개 데이터가 화면은 물론 HTML 페이지 소스코드 어디에도 노출되지 않도록 설계했습니다.

---

## 2. 화면 상의 공개/비공개 시각적 경계 배치

### (1) 상단 공개 영역 (누구나 자유 열람)
- **위치**: `index.html` 상단 헤더부터 섹션 1~10까지
- **내용**: 
  - 엔지니어링 프로필 소개 (Security & Network Engineering)
  - 시스템 공개 대상 정보 3종 (GitHub 소스코드, 기술 스택 명세, 커뮤니티 피드백)
  - 시스템 보호 정보 3종 (DB 마스터키, 인프라 관리자 계정, 방문자 IP)
  - 공인 자격증 및 실무 경험 아카이브
  - 커뮤니티 방명록 피드백
- **접근 통제**: 인증 절차 없이 브라우저 첫 접속 즉시 100% 렌더링

### (2) 하단 비공개 시크릿 볼트 영역 (패스키 소유자만 복호화)
- **위치**: `index.html#passkeyVaultSection` (섹션 11)
- **시각적 인디케이터**:
  - 외곽선: 2px 골드 테두리 (`border-2 border-[#ba9578]`) 및 깊은 다크 방사형 그라데이션 배경
  - 상단 뱃지: `[🔒 비공개 잠김 상태]` (앰버 펄스 애니메이션)
  - 경계 배너: `공개 영역과 비공개 영역의 완전한 물리적 격리` 안내 문구 명시
  - 상태 전환: 비로그인 상태 시 자물쇠 안내 및 패스키 로그인 버튼만 노출되며, 패스키 인증 성공 시에만 초록색 `[🔓 패스키 해제됨]` 뱃지와 함께 비공개 데이터 3종이 동적 렌더링됨

## 3. 비공개 볼트에 보관된 3대 항목 명세 (가상 전문 데이터)

본 볼트에 보관된 데이터는 심사 기준에 부합하도록 실제 주민등록번호나 전화번호 같은 민감 개인정보를 일체 배제하고, 엔지니어링 전문성을 담아 정교하게 작성된 3대 가상 데이터로 구성되었습니다:

| 번호 | 비공개 항목 구분 | 상세 제목 | 주요 보관 내용 요약 |
|:---:|:---|:---|:---|
| **01** | **준비 중인 프로젝트 메모** | Zero-Trust eBPF 기반 클라우드 컨테이너 실시간 침입 탐지 및 방화벽 엔진 | 리눅스 커널 레벨(eBPF XDP)에서 인바운드 패킷을 1ms 미만에 계측·차단하는 차세대 보안 데몬 아키텍처 및 프로토타입 현황 |
| **02** | **지원하려는 곳 목록** | 2026 하반기 테크 기업 핵심 인프라 & 제로트러스트 보안 엔지니어링 포지션 분석 | SK텔레콤 Core Network 보안, 토스/카카오페이 금융 FIDO2 패스키 보안, 네이버클라우드 Security Platform 요구역량 분석 및 기술 인터뷰 전략 |
| **03** | **스스로 쓰는 회고** | 동시성 대량 트래픽 상황에서의 TCP 소켓 자원 고갈(TIME_WAIT) 장애 분석과 교훈 | 피크타임 초당 4,500 RPS 인입 시 발생한 Ephemeral Port 고갈 원인 규명, 커넥션 풀링 및 `tcp_tw_reuse` 튜닝을 통해 얻은 엔지니어링 철학 |

## 4. 비로그인 상태에서의 비공개 내용 미노출 및 소스코드 검증

### (1) 브라우저 화면 검증
- 패스키로 로그인하지 않은 초기 접속 상태에서는 상기 3대 비공개 데이터(제목, 본문, 세부내용)가 화면 어디에도 렌더링되지 않으며, 비공개 볼트 게이트 안내창만 나타납니다.

### (2) HTML 페이지 소스코드 검증 (하드코딩 배제 확인)
- 비공개 데이터는 프론트엔드 HTML 파일에 정적으로 포함되어 있지 않고, 백엔드 데이터베이스(`api/passkey.js`)에 격리되어 있습니다.
- 로그인하지 않은 상태에서 브라우저 '페이지 소스 보기'(`Ctrl+U`) 또는 `curl -s https://skt-aleph-gilt.vercel.app/` 명령으로 HTML 원문을 다운로드하여 검색한 결과:
  - `"Zero-Trust eBPF"` 검색 결과: **0건 (미포함)**
  - `"SK텔레콤 Core Network"` 검색 결과: **0건 (미포함)**
  - `"TIME_WAIT"` 검색 결과: **0건 (미포함)**
- 즉, 화면에서만 `display: none`으로 숨긴 눈속임이 아니라, 서버에서 인증된 세션이 없을 때는 데이터 자체가 클라이언트로 전송되지 않음을 확인했습니다.

## 5. 무인증 직접 API 요청 시 401 Unauthorized 차단 증적

패스키 인증을 거치지 않은 악의적 사용자가 브라우저 UI를 우회하여 백엔드 비공개 볼트 엔드포인트(`GET /api/passkey?action=get_secrets`)를 직접 호출했을 때의 차단 트랜잭션입니다:

### [요청 트랜잭션: Authorization 헤더 없이 비공개 주소 호출]
```http
GET /api/passkey?action=get_secrets HTTP/1.1
Host: skt-aleph-gilt.vercel.app
User-Agent: Mozilla/5.0 (Windows NT 10.0; Win64; x64)
Accept: application/json
```

### [응답 트랜잭션: 서버의 401 거절 응답]
```http
HTTP/1.1 401 Unauthorized
Content-Type: application/json; charset=utf-8
Access-Control-Allow-Origin: *
Date: Mon, 21 Sep 2026 00:15:20 GMT

{
  "success": false,
  "error": "UNAUTHORIZED_ACCESS",
  "message": "패스키 인증 토큰이 없거나 유효하지 않습니다. 비공개 볼트에 접근할 수 없습니다."
}
```

- **검증 결과**: HTTP 401 Unauthorized 코드로 즉시 거절되며, 응답 본문에 비공개 자료가 단 1건도 포함되지 않음(`dataLeakCount: 0`)을 실증하였습니다.
