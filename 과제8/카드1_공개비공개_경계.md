# 카드 1: 공개 영역과 비공개 영역의 분리 및 경계 구축 보고서

## 1. 개요 및 목적
1번 과제에서 구축한 신재원의 공개 소개 페이지(`index.html`)는 누구나 접근할 수 있도록 100% 온전히 유지하면서, 나만의 핵심 역량과 실증 사례를 안전하게 보호할 수 있는 **[🔒 비공개 영역 — 핵심 역량과 실증 사례]** 자리를 새로 구축했습니다.  
페이지 내에 **공개 영역 박스**와 **비공개 영역 박스**를 시각적·물리적·네트워크 계층에서 명확히 양분 분리하여, 패스키 인증 없이는 비공개 핵심 역량 데이터가 화면은 물론 HTML 페이지 소스코드 어디에도 노출되지 않도록 설계했습니다.

## 2. 화면 상의 공개/비공개 시각적 경계 배치

```
┌─────────────────────────────────────────────────────────────┐
│ 🌐 [공개 영역 박스] (Public Area) - 누구나 자유 열람 가능        │
│  ├─ 1. 프로필 소개 (Security & Network Engineering)           │
│  ├─ 2. 시스템 공개 및 보호 범위 (시스템 목적 & 공개/보호 그리드) │
│  └─ 3. 실시간 피드백 및 소통 (Supabase DB 방명록)             │
└─────────────────────────────────────────────────────────────┘
                               ↓ (상하 물리적 분리)
┌─────────────────────────────────────────────────────────────┐
│ 🔒 [비공개 영역 박스] (Private Area) - 패스키 인증 필수         │
│  ├─ 골드 테두리 (border-2 border-[#ba9578]) & 전용 배경       │
│  ├─ 미인증 상태: [🔒 비공개 잠김 상태] 및 패스키 로그인 게이트 │
│  └─ 인증 완료 시: [📂 핵심 역량 및 실증 사례 3종 (STAR 카드)]  │
│       ├─ 1. 계획하고 정리할 때 (자격 로드맵 & 인라인 근거)   │
│       ├─ 2. 문제가 발생했을 때 (IDS 트러블슈팅 & 인라인 근거)│
│       └─ 3. 팀원과 상호작용할 때 (협업 피드백 & 인라인 근거) │
│  ├─ 기기 분실 대비 다중 패스키 관리 (2개 등록, 1개 삭제 실증) │
│  └─ 4대 보안 공격 방어 실시간 샌드박스 콘솔                   │
└─────────────────────────────────────────────────────────────┘
```

### (1) 상단 공개 영역 박스 (누구나 자유 열람)
- **컨테이너**: `index.html` 내 `<div id="publicAreaContainer">`
- **시각적 디자인**: 회색 외곽선(`border-2 border-zinc-700/80`), 다크 백그라운드(`bg-[#0d0d11]`), 상단 에메랄드 뱃지 `[🌐 PUBLIC AREA • 누구나 자유 열람 가능 • 무인증 공개]`
- **포함 섹션**: 
  - 1. 엔지니어링 프로필 소개 (Security & Network Engineering)
  - 2. 시스템 공개 및 보호 범위 (공개 3종 / 보호 3종 / 라이브 주소)
  - 3. 실시간 피드백 및 소통 (방명록 작성 및 피드 실시간 연동)
- **접근 통제**: 인증 절차 없이 브라우저 첫 접속 즉시 100% 렌더링

### (2) 하단 비공개 영역 박스 (패스키 소유자만 열람)
- **컨테이너**: `index.html` 내 `<section id="passkeyVaultSection">`
- **시각적 디자인**: 2px 골드 테두리 (`border-2 border-[#ba9578]`), 깊은 브라운-다크 방사형 그라데이션 배경, 상단 뱃지 `[WEBAUTHN • FIDO2 PASSKEY • 비밀번호 제로 • 과제 8]`
- **상태 전환**: 
  - **비로그인 상태**: 앰버 펄스 애니메이션 `[🔒 비공개 잠김 상태]` 뱃지와 함께 패스키 서명 로그인 버튼만 노출되며, 핵심 역량 텍스트는 일체 노출되지 않음
  - **패스키 인증 완료 상태**: 에메랄드 `[🔓 패스키 인증 성공]` 뱃지, 세션 카운트다운 타이머(1시간), 로그아웃 버튼과 함께 서버에서 전달받은 **핵심 역량과 실증 사례 3종 (STAR 카드 + 인라인 근거 토글)**이 동적으로 렌더링됨

## 3. 비공개 영역에 보관된 핵심 역량 3대 항목 명세

비공개 영역은 신재원 엔지니어의 핵심 역량 3종과 실증 사례(상황·행동·결과·근거)로 구성되며, 실제 주민등록번호나 전화번호 같은 민감 개인정보는 배제되었습니다:

| 번호 | 핵심 역량 구분 | 상세 제목 | STAR 및 실무 근거 요약 |
|:---:|:---|:---|:---|
| **01** | **실행력 / 계획** | 1. 계획하고 정리할 때 — 분석 기반의 목표 수립과 단계별 실행력 | - **상황**: 보안/네트워크 분야의 체계적 학습 로드맵 수립 필요<br>- **행동**: 채용공고·산업 뉴스 분석 매트릭스 수립 및 매일 실천<br>- **결과**: 정보보안산업기사, 네트워크관리사 2급, 리눅스마스터 2급 취득<br>- **근거**: 공인 기술 자격 취득 내역 및 커리어 로드맵 증빙 토글 |
| **02** | **문제 해결 / 분석** | 2. 문제가 발생했을 때 — 근본 원인을 끝까지 파고드는 집요함 | - **상황**: 공격 패킷 유입 시 IDS 엔진 미탐지 원인불명 오류 발생<br>- **행동**: 가상 브리지 promiscuous 모드 및 커널 패킷 경로 역추적<br>- **결과**: 가상 브리지 바인딩 결함 규명 및 탐지 파이프라인 100% 정상화<br>- **근거**: IDS 미탐지 오류 원인 규명 및 트러블슈팅 커널 로그 토글 |
| **03** | **협업 / 시너지** | 3. 팀원과 상호작용할 때 — 공감과 칭찬으로 이끌어내는 협업 시너지 | - **상황**: 일정 압박 및 복잡한 기술 난이도로 인한 경직된 협업 환경<br>- **행동**: 작은 커밋에도 적극적 칭찬, 난관 봉착 동료와 화면 공유 해결<br>- **결과**: 마찰 없는 프로젝트 완수 및 동료들의 진심 어린 감사 피드백<br>- **근거**: 팀 협업 소통 프로세스 및 동료 피드백 발췌 기록 토글 |

## 4. 비로그인 상태에서의 비공개 내용 미노출 및 소스코드 검증

### (1) 브라우저 화면 검증
- 패스키로 로그인하지 않은 상태에서는 상기 3대 핵심 역량 데이터(상황, 행동, 결과, 근거)가 화면 어디에도 노출되지 않으며, 오직 잠금 안내와 패스키 로그인 버튼만 표시됩니다.

### (2) HTML 페이지 소스코드 검증 (하드코딩 완전 배제)
- 비공개 데이터는 프론트엔드 HTML 파일에 정적으로 포함되어 있지 않고, 백엔드 데이터베이스(`api/passkey.js`)에 격리되어 있습니다.
- 로그인하지 않은 상태에서 브라우저 '페이지 소스 보기'(`Ctrl+U`) 또는 `curl -s https://skt-aleph-gilt.vercel.app/` 명령으로 HTML 원문을 다운로드하여 검색한 결과:
  - `"정보보안산업기사"` 검색 결과: **0건 (미포함)**
  - `"네트워크관리사"` 검색 결과: **0건 (미포함)**
  - `"promiscuous"` 검색 결과: **0건 (미포함)**
  - `"침입 탐지 시스템"` 검색 결과: **0건 (미포함)**
- 즉, 화면에서만 숨긴 눈속임이 아니라, 서버에서 패스키 서명 인증을 통과하기 전에는 데이터 자체가 클라이언트로 전송되지 않음을 실증하였습니다.

## 5. 무인증 직접 API 요청 시 401 Unauthorized 차단 증적

패스키 인증을 거치지 않은 비인가자가 브라우저 UI를 우회하여 백엔드 비공개 엔드포인트(`GET /api/passkey?action=get_secrets`)를 직접 호출했을 때의 차단 트랜잭션입니다:

### [요청 트랜잭션: Authorization 헤더 없이 비공개 주소 호출]
```http
GET /api/passkey?action=get_secrets HTTP/1.1
Host: skt-aleph-gilt.vercel.app
User-Agent: Mozilla/5.0 (Windows NT 10.0; Win64; x64)
Accept: application/json
```

### [응답 트랜잭션: 서버의 401 거절 응답]
```http
HTTP/1.1 401 Unauthorized
Content-Type: application/json; charset=utf-8
Access-Control-Allow-Origin: *
Date: Mon, 21 Sep 2026 00:15:20 GMT

{
  "success": false,
  "error": "UNAUTHORIZED_ACCESS",
  "message": "패스키 인증 토큰이 없거나 유효하지 않습니다. 비공개 볼트에 접근할 수 없습니다."
}
```

- **검증 결과**: HTTP 401 Unauthorized 코드로 즉시 거절되며, 응답 본문에 핵심 역량 자료가 단 1건도 포함되지 않음(`dataLeakCount: 0`)을 실증하였습니다.
