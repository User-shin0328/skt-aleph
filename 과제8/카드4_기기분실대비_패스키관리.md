# 카드 4: 기기 분실 대비 다중 패스키 관리 및 복구 실증 보고서

## 1. 개요 및 배경
패스키(Passkey)는 특정 기기의 하드웨어 보안 영역(TPM, Secure Enclave 등)에 개인키가 종속(Bound)되어 있습니다. 따라서 등록된 패스키가 오직 하나뿐일 때 해당 기기를 분실·침수·파손하면 계정에 영구히 접근할 수 없게 되는 치명적인 고립 문제가 발생합니다.  
이를 방지하기 위해 본 시스템은 **한 계정에 2개 이상의 패스키를 등록**할 수 있도록 설계하였으며, 분실 기기의 패스키를 원격으로 삭제한 뒤에도 **남아있는 예비 패스키로 정상 로그인**할 수 있음을 실증합니다.

---

## 2. 한 계정에 패스키 2개 등록 상태 실증 (마스터 PC + 승인 보조 기기)

`runner_shin` 본인 계정에 마스터 컴퓨터 및 승인 코드를 통해 등록된 2개의 패스키 정보는 다음과 같습니다:

| 번호 | 패스키 식별자 (Credential ID) | 사람이 알아볼 수 있는 이름 | 인증기 유형 및 저장소 | 등록 일시 (KST) | 서명 카운터 |
|:---:|:---|:---|:---|:---|:---:|
| **1** | `cred_master_pc_shin` | **신재원 마스터 컴퓨터 (현재 인가 기기)** | PC 내장 TPM 2.0 및 로컬 전용 보안 저장소 (내장 플랫폼) | 2026-09-20 22:00:00 | 1회 |
| **2** | `cred_shin_galaxy_phone` | **신재원 갤럭시 스마트폰 (승인 보조 기기)** | Knox 보안 하드웨어 및 모바일 패스키 저장소 (보조 기기) | 2026-09-21 02:00:00 | 2회 |

### 화면 UI 검증
로그인 후 비공개 영역 내 [📱 기기 분실 대비 다중 패스키 관리 목록] 테이블에서 상기 2개 패스키의 이름, 등록일시, 서명 횟수, 그리고 각각의 [🗑️ 분실 삭제] 버튼이 정상 표시됨을 확인했습니다. 또한 상단에 [📱 새 기기 패스키 발급] 버튼이 제공되어 마스터 컴퓨터에서 보조 기기용 6자리 승인 코드를 발급할 수 있습니다.

## 3. 패스키 1개 삭제(분실 기기 해제) 트랜잭션

사용자가 스마트폰을 분실했다고 가정하고, 마스터 컴퓨터로 접속하여 분실된 스마트폰의 패스키(`cred_shin_galaxy_phone`)를 삭제한 트랜잭션입니다:

### [요청: 특정 패스키 삭제 API 호출]
```http
POST /api/passkey?action=delete_key HTTP/1.1
Host: skt-aleph-gilt.vercel.app
Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...[토큰 마스킹]
Content-Type: application/json

{
  "credentialId": "cred_shin_galaxy_phone"
}
```

### [응답: 삭제 성공 및 잔여 키 목록 반환]
```http
HTTP/1.1 200 OK
Content-Type: application/json; charset=utf-8

{
  "success": true,
  "message": "패스키 [신재원 갤럭시 스마트폰 (승인 보조 기기)]가 성공적으로 삭제(등록 해제)되었습니다.",
  "deletedKeyId": "cred_shin_galaxy_phone",
  "remainingKeysCount": 1,
  "remainingKeys": [
    {
      "id": "cred_master_pc_shin",
      "name": "신재원 마스터 컴퓨터 (현재 인가 기기)"
    }
  ],
  "allKeysExhausted": false,
  "policyNotice": "기기를 분실한 경우 남은 정상 패스키를 사용하여 계속 안전하게 로그인할 수 있습니다."
}
```

## 4. 삭제 후 잔여 패스키 로그인 성공 vs 삭제된 패스키 로그인 실패 비교

### (1) 남은 마스터 컴퓨터 패스키로 로그인 시도 &rarr; [성공]
남아있는 `cred_master_pc_shin`으로 로그인을 시도했을 때의 결과입니다:

```http
POST /api/passkey?action=login_verify HTTP/1.1
Host: skt-aleph-gilt.vercel.app
Content-Type: application/json

{
  "username": "runner_shin",
  "credentialId": "cred_master_pc_shin",
  "clientDataJSON": "eyJ0eXBlIjoid2ViYXV0aG4uZ2V0IiwiY2hhbGxlbmdlIjoiWjRiQ...생략",
  "authenticatorData": "SZYN5YgOjGh0NBcPZHZgW4_krrmihjLHmVzzuoMdl2MBAAAAJA",
  "signature": "MEQCID_valid_signature_from_master_pc...생략"
}
```

```http
HTTP/1.1 200 OK
Content-Type: application/json; charset=utf-8

{
  "success": true,
  "message": "[신재원 마스터 컴퓨터 (현재 인가 기기)] 패스키 서명 검증이 통과되었습니다. 비공개 볼트가 열렸습니다.",
  "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...[새 토큰 마스킹]",
  "user": {
    "username": "runner_shin",
    "displayName": "신재원"
  },
  "usedCredential": {
    "id": "cred_master_pc_shin",
    "name": "신재원 마스터 컴퓨터 (현재 인가 기기)",
    "signCount": 2
  }
}
```
- **결과**: 하나의 키가 삭제되었더라도 남아있는 마스터 컴퓨터 키로 즉시 로그인되어 비공개 핵심 역량이 완벽히 열립니다.

---

### (2) 분실/삭제된 스마트폰 패스키로 로그인 시도 &rarr; [403 거절]
분실 기기를 습득한 제3자가 스마트폰의 삭제된 패스키(`cred_shin_galaxy_phone`)로 로그인을 시도한 경우입니다:

```http
POST /api/passkey?action=login_verify HTTP/1.1
Host: skt-aleph-gilt.vercel.app
Content-Type: application/json

{
  "username": "runner_shin",
  "credentialId": "cred_shin_galaxy_phone",
  "clientDataJSON": "eyJ0eXBlIjoid2ViYXV0aG4uZ2V0IiwiY2hhbGxlbmdlIjoiWjRiQ...생략",
  "authenticatorData": "SZYN5YgOjGh0NBcPZHZgW4_krrmihjLHmVzzuoMdl2MBAAAAJA",
  "signature": "MEQCID_signature_from_deleted_key...생략"
}
```

```http
HTTP/1.1 403 Forbidden
Content-Type: application/json; charset=utf-8

{
  "success": false,
  "error": "DELETED_CREDENTIAL",
  "message": "이 패스키는 기기 분실로 인해 삭제되었습니다. 더 이상 로그인할 수 없습니다.",
  "credentialId": "cred_shin_galaxy_phone"
}
```
- **결과**: 서버의 `deletedCredentials` 이력 대조를 통해 삭제된 패스키로 판별되어 즉시 `HTTP 403 Forbidden`으로 거절되며, 비공개 볼트는 전혀 열리지 않습니다.

## 5. 모든 패스키가 삭제(0개)되었을 때의 정책과 처리

만약 사용자가 등록된 마지막 패스키까지 모두 삭제하거나 실수로 모든 키를 잃어버렸을 경우:
1. **화면 안내**: `경고: 등록된 패스키가 0개입니다. 비공개 볼트에 진입할 수 없습니다.` 경고 배너가 표시됩니다.
2. **로그인 차단**: `login_options` 요청 시 `HTTP 404 (USER_OR_CREDENTIALS_NOT_FOUND)` 에러가 발생하여 잠긴 비공개 영역에 절대 접근할 수 없습니다.
3. **복구 절차**: 
   - 사용자는 화면의 `[➕ 새 패스키 등록하기]` 버튼을 통해 새로운 기기에서 신규 공개키 쌍을 발급받아 등록해야만 다시 비공개 볼트를 활성화할 수 있도록 안전 복구 경로를 제공합니다.
