# 카드 2: 비밀번호 보관과 단방향 해싱

## 1. 비밀번호 보관 및 암호화 설계

본 다이어리에서는 사용자 비밀번호를 데이터베이스나 메모리에 **절대로 평문(Plaintext)으로 저장하지 않습니다.** 가입 또는 로그인 시 전달받은 비밀번호는 서버 수신 즉시 암호학적 단방향 해시 함수를 거쳐 변환되며, 원본 비밀번호는 메모리에서 즉시 가비지 컬렉션됩니다.

### 단방향 솔트 해싱 메커니즘 (PBKDF2-HMAC-SHA256)
- **알고리즘:** `PBKDF2` (Password-Based Key Derivation Function 2)
- **의사난수 함수:** `HMAC-SHA256`
- **반복 횟수 (Iterations):** `100,000`회 (NIST 권고 기준 부합)
- **고유 Salt:** 계정 생성 시마다 `crypto.randomBytes(32)`를 호출하여 32바이트(256비트) 암호학적 무작위 값을 생성하여 계정 레코드에 함께 보관
- **파생 키 길이:** `64`바이트 (512비트), Hex 인코딩 보관
- **타이밍 공격(Timing Attack) 방어:** 문자열 동등 비교 시 단순 `===` 연산자를 사용하지 않고, 일정한 연산 시간을 보장하는 `crypto.timingSafeEqual` 함수를 사용하여 해시 길이와 문자 일치 여부를 기반으로 한 부채널 분석 공격을 차단

```javascript
// api/diary.js 핵심 구현 발췌
function hashPassword(password, saltHex = null) {
  const salt = saltHex ? Buffer.from(saltHex, 'hex') : crypto.randomBytes(32);
  const derivedKey = crypto.pbkdf2Sync(password, salt, 100000, 64, 'sha256');
  return {
    salt: salt.toString('hex'),
    hash: derivedKey.toString('hex'),
    iterations: 100000,
    algo: 'pbkdf2-hmac-sha256'
  };
}

function verifyPassword(password, storedHashHex, storedSaltHex) {
  const { hash } = hashPassword(password, storedSaltHex);
  const bufA = Buffer.from(hash, 'hex');
  const bufB = Buffer.from(storedHashHex, 'hex');
  if (bufA.length !== bufB.length) return false;
  return crypto.timingSafeEqual(bufA, bufB);
}
```

## 2. 동일 비밀번호 솔트 분리 실증 (레인보우 테이블 무력화 증적)

동일한 비밀번호를 사용하는 복수의 사용자가 존재하더라도, 계정마다 독립적으로 부여되는 32바이트 랜덤 Salt로 인해 최종 생성된 해시 결과가 완전히 달라짐을 검증했습니다.

### 검증 환경 및 시나리오
- **테스트 계정 1:** `runner_shin` (신재원 본인 계정)
- **테스트 계정 2:** `runner_guest` (테스트 게스트 계정)
- **설정 비밀번호:** 두 계정 모두 동일한 비밀번호 `P@ssw0rd123!` 사용

### 실제 서버 검증 트랜잭션 (요청 및 응답)
- **요청:** `GET /api/diary?action=verify_hashes`
- **응답 상태:** `HTTP 200 OK`
- **응답 본문 (JSON):**
