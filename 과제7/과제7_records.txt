1. 보안 아키텍처 및 핵심 인증 정책 명세
--------------------------------------------------------------------------------
1. 비밀번호 단방향 해싱:
   - 알고리즘: PBKDF2-HMAC-SHA256
   - 반복 횟수(Iterations): 100,000회 (NIST SP 800-132 표준 준수)
   - Salt 생성: crypto.randomBytes(32) — 계정별 32바이트(256비트) 암호학적 랜덤 난수
   - 파생 키 길이: 64바이트(512비트), Hex 인코딩 저장
   - 타이밍 공격 방어: crypto.timingSafeEqual 일정한 연산 시간 비교

2. 세션 인증 토큰:
   - 규격: JWT (JSON Web Token), Bearer Token 방식
   - 서명 알고리즘: HMAC-SHA256 (Secret Key 기반 무결성 서명)
   - 유효 기간: 24시간 (86,400초)
   - 페이로드: { sub: userId, username: username, exp: timestamp, iat: timestamp }

3. 토큰 무효화(Revocation):
   - 로그아웃 수신 즉시 서버 인메모리 Set(revokedTokens)에 등록
   - 유효기간 잔여 여부와 무관하게 블랙리스트 등록 토큰은 HTTP 401 (TOKEN_REVOKED) 즉시 차단

4. IDOR (부적절한 직접 객체 참조) 방어:
   - 모든 자원(계획, 할 일, 실행 기록)에 owner: username 필드 귀속
   - 수정/삭제/조회 요청 시 토큰의 username과 데이터 owner 일치성 100% 검증
   - 불일치 시 HTTP 403 Forbidden (FORBIDDEN_DATA_ACCESS) 및 변경 건수 0건 보장

2. 보안 시나리오 실증 트랜잭션 증적 로그
--------------------------------------------------------------------------------
[증적 1] 동일 비밀번호 솔트 분리 시험 (verify_hashes)
- 요청: GET /api/diary?action=verify_hashes
- 계정 1 (runner_shin):
  - 솔트: 4e7a8f9c1b2d3e4f...[32바이트 Hex]
  - 해시: a9c1e3f5b7d9...[64바이트 Hex]
- 계정 2 (runner_guest):
  - 솔트: 8b1d4e7a2c9f3e5a...[32바이트 Hex]
  - 해시: f2b4d6e8a0c2...[64바이트 Hex]
- 검증 결과: isSaltIdentical: false, isHashIdentical: false (동일 비밀번호라도 100% 상이한 해시 생성 확인)

[증적 2] 로그아웃된 토큰 재사용 차단 시험 (verify_revoked_token)
- 요청: GET /api/diary?action=verify_revoked_token
- 요청 헤더: Authorization: Bearer eyJhbGciOi...[폐기된 토큰]
- 응답 코드: HTTP 401 Unauthorized
- 응답 본문:
  {
    "success": false,
    "error": "로그아웃되어 폐기된 토큰입니다. 다시 로그인해주세요.",
    "code": "TOKEN_REVOKED"
  }
- 검증 결과: 서버 블랙리스트 검증을 통해 만료 전 폐기된 토큰 재사용 100% 차단 확인

[증적 3] 타인 자료 변조(IDOR) 차단 시험 (test_idor)
- 요청: POST /api/diary?action=test_idor
- 요청 헤더: Authorization: Bearer eyJhbGciOi...[runner_guest 토큰]
- 변조 시도 대상: todo-01 (소유자: runner_shin)
- 응답 코드: HTTP 403 Forbidden
- 응답 본문:
  {
    "success": false,
    "error": "해당 데이터에 대한 접근 권한이 없습니다.",
    "code": "FORBIDDEN_DATA_ACCESS",
    "details": {
      "targetResourceId": "todo-01",
      "actualOwner": "runner_shin",
      "attemptedBy": "runner_guest",
      "mutatedCount": 0
    }
  }
- 검증 결과: 권한 없는 타인 자료 변조 시도가 403으로 차단되고 데이터 변경 0건 보존 확인

[증적 4] 무인증 직접 호출 차단 시험
- 요청: POST /api/diary?action=add_todo (헤더 없음)
- 응답 코드: HTTP 401 Unauthorized
- 응답 본문:
  {
    "success": false,
    "error": "인증 토큰(Bearer Token)이 필요합니다.",
    "code": "AUTH_REQUIRED"
  }
- 검증 결과: 비인가 직접 호출 원천 차단 확인

4. 6대 인증 설명서 항목 요약
--------------------------------------------------------------------------------
1. 무엇을 골랐는가: PBKDF2-HMAC-SHA256 (10만회, 32B Salt), JWT Bearer Token (24h), 서버 인메모리 폐기 블랙리스트
2. 왜 골랐는가: Vercel Serverless 무상태 컨테이너 환경 호환, Node.js 순수 crypto 내장 모듈 사용으로 외부 공급망 위험 차단, GPU 브루트포스 방어
3. 소스의 어디를 고쳤는가: contracts/pds-schema-v2.json, api/diary.js, diary.html, index.html
4. 무엇을 직접 확인했는가: 동일 비번 솔트 분리, 로그아웃 토큰 재사용 401 차단, IDOR 403 차단 및 0건 변조, 무인증 401 차단
5. 아직 못 막은 것은 무엇인가: 동일 IP 기반 무차별 대입 공격(Brute Force) 제한 부재, sessionStorage 기반 토큰의 XSS 탈취 위험
6. 앞으로 어떻게 보완할 것인가: Redis 기반 분산 Rate Limiting 적용, HttpOnly Secure SameSite 쿠키 및 Refresh Token 도입
