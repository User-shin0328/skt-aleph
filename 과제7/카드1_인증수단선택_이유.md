# 카드 1: 인증 수단 선택과 그 이유

## 1. 선택한 인증 및 보안 수단

본 프로젝트(플랜두씨 다이어리 2)에서는 공개된 다이어리에 사용자 인증을 적용하여 본인의 계획과 실행 기록을 안전하게 잠그기 위해 다음 3가지 핵심 보안 기술을 선정하여 구현했습니다.

1. **비밀번호 단방향 솔트 해싱 (PBKDF2-HMAC-SHA256)**
   - **반복 횟수 (Iterations):** 100,000회
   - **Salt 규격:** 암호학적으로 안전한 난수 생성기(`crypto.randomBytes`)를 통한 계정별 고유 32바이트(256비트) Salt
   - **출력 키 길이:** 64바이트(512비트), 16진수 문자열 인코딩 보관
   - **타이밍 공격 방어:** `crypto.timingSafeEqual`을 통한 상수 시간 문자열 비교

2. **무상태 사용자 세션 토큰 (JWT, JSON Web Token Bearer)**
   - **서명 알고리즘:** HMAC-SHA256 (대칭키 기반 무결성 및 위변조 검증)
   - **유효 시간:** 24시간 (1일) 타임아웃
   - **전송 방식:** 표준 HTTP 요청 헤더 `Authorization: Bearer <token>`

3. **즉시 토큰 폐기 블랙리스트 메커니즘 (Server Revocation Blacklist)**
   - 로그아웃 요청 수신 즉시 서버 메모리 내 `revokedTokens` 세트에 등록
   - 유효기간이 남아 있더라도 블랙리스트에 등록된 토큰은 즉각 HTTP 401 Unauthorized (TOKEN_REVOKED)로 차단

## 2. 왜 이 기술을 골랐는가 (선택 배경 및 기술적 근거)

### (1) Vercel Serverless 무상태(Stateless) 아키텍처 최적화
서버리스 클라우드 환경에서는 요청마다 독립된 컨테이너가 기동되거나 확장될 수 있습니다. 별도의 세션 DB(세션 클러스터)를 두지 않는 구조에서는, 비밀키로 전자서명된 JWT 토큰을 사용하는 것이 서버 간의 상태 동기화 비용 없이도 각 컨테이너에서 독립적이고 빠른 인가 검증을 수행하는 데 가장 적합합니다.

### (2) 외부 패키지 무설치 및 공급망 보안(Supply Chain Security) 극대화
외부 서드파티 npm 패키지(`bcrypt`, `jsonwebtoken` 등)를 추가할 경우 발생할 수 있는 버전 의존성 충돌, 네이티브 빌드 컴파일 오류, 악성 코드 주입(공급망 공격) 위험을 완전히 배제하기 위해, Node.js 18+ 런타임에 기본 내장된 웹 표준 및 시스템 보안 표준 라이브러리인 `node:crypto`만을 순수하게 활용하여 전 과정을 자체 구현했습니다.

### (3) 레인보우 테이블 및 GPU 병렬 브루트포스(무차별 대입) 공격 무력화
단순 MD5, SHA-1, SHA-256과 같은 단일 라운드 해시는 공격자가 미리 계산해 둔 거대한 역변환 표(Rainbow Table)나 초당 수십억 번의 연산이 가능한 GPU 장비 앞에서 무력합니다.
본 프로젝트에서 채택한 PBKDF2 10만 회 키 스트레칭은 공격자가 단 하나의 암호를 추측하는 데에도 상당한 CPU 자원을 소모하게 강제함으로써 오프라인 사전 공격을 경제적으로 무력화합니다.
