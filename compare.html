📊 2. 집계 결과 : 블라인드 측정 및 진행 순서

편향을 방지하기 위해 AI 모델명을 가리고 실제 계측 지표로만 정량 비교하였으며, 사전 합의된 순서에 따라 단계별로 작업을 집계하였습니다.

STEP 1
사전 기준 확정
고정 검사 10개 정의 및 공통 상한(60분/15회) 확정
STEP 2
도구 A 작업 및 인계
UI 스캐폴딩, 5개 검사 통과 후 커밋 및 HANDOFF.md 인계
STEP 3
도구 B 세션 재개
대화 전문 없이 저장소와 인수인계서만으로 작업 착수
STEP 4
기능 완성 및 완주
남은 결함 5건 해결 및 10개 검사 100% 통과 완료
비교 지표 항목 도구 A [블라인드] 도구 B [블라인드] 공통 상한 / 판정 기준 결과
실제 작업 소요시간 32분 24분 60분 이하 상한 준수
실제 요청 및 호출 횟수 8회 5회 15회 이하 상한 준수
오류 발생 회차 2회 1회 검사 FAIL 발생 실행 회차 계측 완료
검사 통과 수 5 / 10 건 10 / 10 건 10건 고정 100% 완주
검사 삭제·완화·변경 여부 0건 0건 기준 임의 변경 일체 불허 무변경 준수
코드 라인 변동량 (Git Diff) +98줄 / -0줄 +62줄 / -4줄 Git 커밋 기준 재작업 최소화

📑 3. 인수인계 문서 (7칸 표준 프로토콜)

도구 A가 작업을 중단하며 남긴 실제 인수인계서(HANDOFF.md)의 전문 내용입니다. 새로운 도구 B는 이전 대화 내역 일체 없이 아래 7개 항목만으로 작업을 완벽히 재개하였습니다.

📍 2. 현재 상태 (Current State)

기본 계산기 UI 마크업 및 원화→외화 계산 수식(calculateExchange) 작성 완료. 양수 금액 입력 시 정상 동작(검사 5건 통과).

💡 4. 본인 판단 : 도구 선택 기준 및 AI 협업 평가

이번 멀티 LLM 연계 실험을 통해 도출한 다음 작업에서의 도구 선택 기준과 엔지니어링 의사결정 기록입니다.

도구 선택 기준 (Tool Selection Principle)

"대규모 신규 기능의 뼈대 설계와 신속한 스캐폴딩 작업에는 초기 구현 속도가 빠른 도구 A를 우선 투입하고, 세밀한 경계 조건 검증, 예외 방어 및 결함 디버깅 완성 단계에는 완성도가 높은 도구 B를 채택한다."

1. AI에게 맡긴 일

10개 고정 검사의 구체적 입력/기대값 매트릭스 수립, 실시간 환율 계산기 UI 및 예외 방어 수식 코드 작성, 7칸 인수인계 템플릿과 비교 보고서 웹 화면(compare.html) 제작.

2. 직접 판단한 일

과제 4 실시간 환율 계산기를 개선 과제로 최종 선정, 공통 상한선(60분/15회) 및 10개 고정 검사의 엄격성 기준 수립, 블라인드 성능 계측 결과에 기반한 도구 선택 기준 확립.

3. AI 제안을 따르지 않은 일

AI가 초기에 제안한 대화 로그 전문 첨부 방식을 과제 본질(인수인계 품질 시험)에 맞지 않아 전면 기각하고, 오직 순수한 7칸 인수인계서와 Git 커밋만으로 재현되도록 통제함.
