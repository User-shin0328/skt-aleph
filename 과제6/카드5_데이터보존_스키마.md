# 카드 5 — 내 것으로 채우고, 잃지 않게 (Persistence, Schema, Security)

## 1. 개요 및 안전 규약
남의 예시가 아닌 실제 본인의 운동 계획과 기록을 담았으며, 서버 데이터베이스 연동과 계약 스키마 정의, 데이터 백업 파일 내보내기, 스크립트 인젝션(XSS) 방어 및 비밀키 노출 0건을 실증하였습니다.

---

## 2. 서버 데이터베이스 지속성 및 새로고침 복원

- **서버리스 API 엔드포인트**: `REST /api/diary` (Node.js Serverless Function)
- **지속성 검증**:
  - 브라우저를 강력 새로고침(F5)하거나 새 시크릿 창으로 재접속 시, 서버 DB로부터 계획 ID(`plan-running-2026-h2`), 마감일(KST YYYY-MM-DD), 단위(`분`, minute), 실행 기록 3건이 100% 동일한 값으로 복원됨.
  - 네트워크 단절이나 cold start 상황에서도 브라우저 로컬 캐시와의 하이브리드 동기화로 데이터 유실 0건 보장.

---

## 3. 데이터베이스 계약 스키마 명세 (`contracts/pds-schema-v2.json`)

최종 데이터베이스의 표, 항목, 관계, 날짜 및 단위 규칙을 표준 JSON Schema 형식으로 정의하여 저장소에 영구 반영하였습니다:
1. **규칙 (Rules)**:
   - 시간대: `Asia/Seoul` (KST 기준)
   - 날짜 포맷: `YYYY-MM-DD`
   - 시간 포맷: `YYYY-MM-DDTHH:mm`
   - 시간 단위: `minute` (분)
   - 멱등성 규칙: `idempotencyKey` 기반 중복 완료 방어
2. **테이블 (Tables)**:
   - `plans`: 최상위 계획
   - `plan_history`: 수정 전 계획 버전 및 사유 보존
   - `todos`: 계획에 딸린 할 일
   - `execution_logs`: 할 일에 연결된 실제 실행 기록
   - `retrospectives`: 집계 분석 및 피드백 환류
